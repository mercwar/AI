How It Works: Why These 4 Steps Make the AI Smarter (Click to Expand Guide)

The Problem with Normal AI Chats: When you ask a standard AI chat window to build a large app or game all at once, it runs out of memory, forgets earlier files, and breaks connections between scripts. Mercwar AVIS solves this by giving the AI a lightweight table of contents first, then building one file at a time.

1. Why You "Create Your Topic" First

What happens: Your project name, specialty, and folder list lock the AI into a specific developer role before it writes a single line of code.

Why it matters: Instead of guessing what programming language or folder layout you prefer, the AI follows strict rules for where every file lives—preventing messy, unorganized code.

2. Why You "Add a Program" (.ref Blueprint Pack)

What happens: A .ref file is like a master blueprint or shipping manifest. It lists every file's ID, path, and function names—without loading thousands of lines of heavy source code.

Why it matters: Because the blueprint is tiny, the AI keeps the entire project map in its active memory without slowing down or hitting word limits.

3. Why You Paste the Script into a Brand-New Chat Window

What happens: Pasting the setup script as Message #1 programs the chat window with AVIS rules and loads your blueprint into the AI's working memory.

Why it matters: Starting in a fresh chat prevents old conversations from confusing the AI. Waiting for the AI to reply "Ready" confirms that it has read and locked in your blueprint.

4. Why You Build One File at a Time (/body)

What happens: When you type a command like /body GAME-LOOP-001, the AI looks up that exact file in your blueprint, checks which other files depend on it, and writes complete, ready-to-save code for just that file.

Why it matters: Every file is guaranteed to match the rest of your project, and you never get cut-off responses or half-finished code blocks.
